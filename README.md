# Thank You単熟語長文3900+

React Native + Expo + TypeScript で作成した、段階的開発中の英語学習アプリです。今回は **操作できるWeb版の基礎** を実装しています。本番公開・課金・外部契約は行っていません。

## 起動

Node.js 22以上（検証環境: 24.22.1）、npmを使用します。

```bash
cd /workspace/Thank-You-tanjukugo
npm ci
npm run web
```

表示される開発サーバーをブラウザで開いてください。既存のチェックアウトを使います。別worktreeの作成は不要です。
Expo CLIはオフラインモードで起動するため、ローカル開発にExpoアカウントは不要です。初回の依存関係導入にはnpmレジストリへの接続が必要です。`scripts/expo.mjs` がテレメトリとリモートAPI照会を抑制します。TLSやパッケージの整合性確認は無効にしません。

```bash
npm run typecheck
npm test
npm run test:e2e
npm run build:web
node scripts/check-production.mjs
```

E2EはPlaywrightとChromiumを使用します。クラウド環境では `/usr/bin/chromium` が利用可能です。他の環境では `playwright.config.ts` の `executablePath` をローカルのChromiumに合わせてください。本番確認スクリプトは `CHROMIUM_PATH` にも対応します。Python 3を静的ファイル配信に使います。`dist/` はWeb配布用ビルド出力です。デプロイは自動実行しません。

## Vercelへの追加準備

`vercel.json` にインストール `npm ci`、ビルド `npm run build:web`、出力先 `dist`、Framework Preset `Other` 相当の設定を保存しています。現在の実装は `feat/web-learning-foundation` ブランチにあり、`main` にはまだ反映していません。

この環境にはVercelアカウントの認証・プロジェクト連携がありません。アカウント認証後、作業ブランチから `vercel deploy` でプレビューデプロイできます。`--prod` による本番公開は行いません。GitHub連携で追加する際は、この作業ブランチと本番ブランチの設定を確認してください。Vercelの初回ImportからのDeployは本番デプロイになり得るため、プレビューと混同しないでください。

プレビューはリモート上で操作を確認するための配信であり、端末内の保存データは開発環境や別のプレビューURLから自動移行されません。Vercelへの実登録・デプロイ・有料プラン契約はまだ行っていません。

## 実装済み

- 正式名称、ホワイト×ネイビーのレスポンシブホーム、LEVEL 1〜4、前回セクションへの再開。
- LEVEL 1の英単語100語・英熟語50個。固定ID、番号、品詞、発音表記、意味、例文、和訳、短い説明付き。他LEVELは準備中と明示。
- セクション一覧、教材一覧・独立詳細、前後移動・タッチスワイプ、フィルタと一覧スクロール位置の復帰。
- 4択＋わからない、重複のない選択肢、番号順・ランダム順、10/20/30/50/全件、即時解説、間違えた教材だけの再練習。
- 選択式と記述式の連続正解数・習得状態・回答履歴を完全分離。2連続正解で該当形式のみ習得。不正解・わからないで該当形式のみリセット。
- 開発時のPremium検証モードによる記述式・お気に入り。英語は前後空白と大文字小文字を無視し、それ以外は明示した別解のみ許容。熟語は語数と最初の単語の頭文字をヒントに、語別入力。
- 横断検索、LEVEL別・教材別・形式別の習得集計、直近50件の回答履歴表示（全履歴を保存）。
- オリジナルのWeb Audio合成によるタップ・正解・不正解音。連打と重なりを抑制。設定を保存。
- Web Speech APIによる英語発音と選択式の自動再生。効果音と独立した設定。音声の有無・音質は端末に依存。
- AsyncStorageによる端末内保存（WebではlocalStorage）。読み込み完了後に保存を開始し、書き込みを直列化。保存失敗の表示と再試行、破損・未知形式データの保護。

Premium検証スイッチは `__DEV__` のときだけ存在し、リロードでOFFになります。記述式の過去データは維持します。**本番ビルドには購入機能も検証モードもありません**。現段階の記述式検証には開発サーバーを使用してください。

## データ設計と追加方法

`src/data/entries.json` はコードから独立した検証用オリジナル教材です。`src/model.ts` の `Entry` に従って追加します。IDは公開後に変更・再採番しないでください。`kind + level + number` を初期IDに用いています。将来番号や収録順が変わってもIDは保持します。

- `id`, `kind`, `level`, `section`, `number` により最大4LEVEL・種別・セクションを識別。
- `acceptedAnswers` は記述式の明示的な別解。無条件のスペル近似採点はしません。
- `progress[entryId][choice | written]` に習得状態・連続正解・各形式の履歴を保存。保存スキーマの `version` は1。変更時には移行処理を追加し、未知の形式を上書きしない方針です。
- 追加教材を読み込むとセクション一覧と進捗集計に自動反映。未収録LEVELには進捗の偽データを作りません。最終収録予定数は `src/data/index.ts` に定義。
- `validateEntries` とテストでID/教材の重複、基本的な必須項目、4択の正解一意性を検証。意味の専門的な校閲・全発音表記のレビューは正式教材制作時に別途行います。
- 将来のクラウドDBでは `(user_id, entry_id, mode)` を習得レコードのキーにし、試験合格は `(user_id, level, kind, section, mode)` の別テーブル、称号は削除しない別レコードとします。現在の `permanentAwards` は将来用の保全フィールドで、称号獲得はまだ実装していません。
- 長文は語彙と異なる教材型（安定ID、LEVEL、形式、本文、設問、選択肢と正答、和訳・根拠・構文解説）として追加し、語彙の習得キーと混在させない設計方針です。

## テスト範囲

単体テストは教材150件、両形式の独立性、不正解のリセット、履歴の不変性、4択の正解一意性、記述式採点、保存の往復と破損検出を実行します。

ブラウザE2Eは実際の画面で選択式/記述式を各2周し習得させ、片方の不正解が他方を変えないこと、更新後の履歴・設定、検索、スマホ幅、熟語入力、お気に入りと一覧位置、破損データの保護を検証します。音声APIのモックで効果音OFFと発音ONの独立性も検証します。

本番スモークテストは出力された `dist/` を配信し、Premium検証スイッチがないこと、実際のWeb Audioでタップ/正解/不正解の音源ノードが起動すること、画面エラーがないことを確認します。未実装の試験・長文・クラウド同期に関する最終仕様のテストは未実施です。
